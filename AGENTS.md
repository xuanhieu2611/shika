# Shika

Mac desktop app for running a few coding agents at once. The author adds a repo, presses New, and gets a git worktree plus the CLI they already pay for. They write the prompt, test, and push. Shika does not wrap a model API.

Update this file when behavior or a toolchain trap changes. Keep it short. The guides in `docs/` hold the detail.

## Commit attribution

Never add yourself or any AI agent (Cursor, Claude, Codex, Pi, or others) as a commit author or co-author. Do not add AI `Co-authored-by` trailers or agent attribution to commit messages. Keep authorship with the human author. This applies to every agent, including merge commits.

## Product rules

Each rule lives with the feature it governs: the guides in `docs/` (start at `docs/README.md`), `design/DESIGN.md` for anything visible, and the product principles and non-goals in `CONTRIBUTING.md`. `docs/tasks-and-worktrees.md` covers the core lifecycle: worktree creation, base branch, dirty and unpushed checks, Close, and leftovers. Do not relitigate these rules; a change in direction comes from the author, and the guide changes with the code.

In particular:

- Desktop app, pure Rust on GPUI, Mac only. No kanban, no flat session list, no project tabs, no splits beyond the resizable agent column and the read-only Changes panel, no second visible terminal, no editor, no conversation history.
- GPUI comes from the `zed-industries/zed` git repo at one pinned `rev`. The terminal engine is `alacritty_terminal`, and its types stay inside one module of `shika-terminal`. Never copy from Zed's `terminal` or `terminal_view` crates; they are GPL-3.0. Check GPUI names against the pinned `rev`, not against docs for another version.
- The chrome uses the system font. The terminal uses the bundled JetBrains Mono, with Menlo as the fallback. Not SF Mono: GPUI loads only its regular weight.
- This build launches Claude Code, Codex, Cursor CLI, and Pi. Kiro waits.
- Shika creates the worktree. Never pass Cursor's `--worktree`. Do not invent a CLI flag; the launch args below were taken from each binary's `--help`.
- A `git push` in the shell does not remove the card. The author closes the card. A push typed inside the agent CLI is ignored.
- Close asks before throwing away uncommitted work or unpushed commits: discard, or push when the tree is clean. Close does not commit.
- Projects persist. Live sessions do not come back after a relaunch. Quit does not delete worktrees.
- One terminal view per live PTY, kept alive when hidden, so a full PTY buffer cannot stall the CLI. New creates only the pinned agent tab. `+` or Cmd+T adds independent shell tabs in that worktree; each keeps running until closed. Tabs belong to the task, with one visible terminal and no splits. Before changing tabs, read `docs/terminal-tabs.md` for the decision, ownership/lifecycle map, startup and focus traps, debugging, and contributor guardrails.

## CLIs and launch arguments

Checked from each binary's `--help`: Claude Code and Cursor CLI on 2026-10-03, Codex CLI 0.160.0 and Pi 1.0.0 on 2026-10-05. Do not pass `agent --worktree` or `codex --worktree`. Recheck `--help` before changing a flag.

| Preset | Binary | Launch args |
| --- | --- | --- |
| Claude Code | `claude` | `--dangerously-skip-permissions` |
| Codex | `codex` | `--dangerously-bypass-approvals-and-sandbox` |
| Cursor CLI | `agent` | `--yolo --trust --sandbox disabled` |
| Pi | `pi` | `--approve` |

Pi does not ask before a tool call; `--approve` skips its project-trust prompt on a new worktree. Kiro is not in this build. Codex also gets `-c 'projects={"<worktree>"={trust_level="trusted"}}'` (the worktree path, TOML-escaped, built by `agents::launch_flags`) so its "Trust this folder?" dialog does not block a fresh worktree; it is a per-process override that writes no global config. Verified in a real pty with Codex 0.161.0 on 2026-10-09; the dotted `projects."<path>".trust_level` form is ignored. Claude Code's trust dialog has no documented session-local flag and still appears once per new worktree. Details in `docs/tasks-and-worktrees.md`.

## Where the build is

The GPUI app is implemented in `crates/shika`. The Tauri, React, xterm.js, Node, and Vite app has been removed. The app includes project persistence, draft worktrees, cards, the keyboard map, task-scoped terminal tabs, task branch naming from the CLI's own session title, a two-second quiet timer, native notifications with the system alert sound, discard-or-push close, and explicit leftovers cleanup.

Optional preparation: `.shika/worktrees.json` in the main checkout declares `setup-worktree` commands, literal ignored `copy-files`, and `timeout-seconds` (default 600). New asks for local approval, again on parsed configuration changes. Copy/setup finish before the CLI starts, with two setup slots, output in the existing terminal, cancel, and fresh-worktree retry. Setup typing is suppressed; startup query replies must still reach the agent. Active preparations stay journaled but out of disposable leftovers. Failures remove only provably untouched trees; changed or unverifiable work stays for explicit cleanup. Quit/project removal cancel setup and retain trees. No configuration means the existing flow, no pooling, inferred installs, or execution of Cursor/Codex configuration. Commands are trusted code, not a sandbox, and must not daemonize. Before modifying this feature, read `docs/worktree-preparation.md`: decisions, launch/cleanup lifecycle, symbol map, input-phase traps, debugging fixture, and extension guardrails.

Branch names: the first prompt line names the branch at once. About a second later the CLI's own session title, read from Claude Code's, Codex's, Cursor's, or Pi's private files, renames it once, without the project name and with the optional Settings prefix. Pi has a title only when one was set. Those files are not a public API, so reading them is best effort; on any failure the prompt name stays. Rename task (card menu, Agent menu, Cmd+Shift+R) changes the live session's display name and future Create PR title defaults only, never Git or CLI files. Manual names win over automatic display titles; automatic branch naming continues independently. Memory only, 1 to 80 Unicode characters, available after the CLI starts. `docs/task-names.md` is the public FAQ and contributor contract; read it before changing manual naming. A branch already on a remote is never renamed by Shika. External Git renames are followed only with an explicit reflog rename chain and no surviving original branch; the card and journal update, while real branch switches require separate verified Close recovery and never transfer ownership. `docs/branch-naming.md` has the rules, the why, the code map, the CLI file formats, and how to debug it.

Close offers explicit branch-switch recovery when both recorded and current branches exist, the worktree is clean, and neither branch has unpublished commits outside the accepted base or remote-tracking refs. Confirmation stops all task PTYs and removes only the worktree/card; both local branches stay. Dirty/unpublished work, missing refs, and detached HEAD block recovery. Ordinary discard/push still require task branch identity. Switching never transfers ownership. Read `docs/branch-switch-close.md` before modifying close: safety proof, preview/rechecks, code map, debugging, and contributor guardrails.

Lead (spike): Cmd+L or Agent > New Lead starts one Lead per project, an agent CLI in its own detached worktree (`.worktrees/shika-lead-<id>`, no branch, no setup) that the author talks to. It runs `shika help`, `tasks`, `new`, `status`, `wait`, `read`, `diff`, `send`, `key`, `pr`, and `close` against a local socket (`SHIKA_SOCKET`, `SHIKA_TOKEN`; the app binary is the client) to start up to 4 ordinary worker cards, marked "from Lead", wait for them, read their terminals and diffs, and answer their dialogs. `send`, `key`, `pr`, and `close` work only on workers it started, and are refused while the worker is Working (except `key escape`), when its CLI has exited, or when the author left unsent typed text in that terminal. A worker never takes selection or focus. A launch prompt counts as the first submission, so the card works and notifies. Doorbell, on for every Lead: when workers it started settle (Ready, Asking, Exited) and no `wait` reported them, Shika submits one `[shika] Workers changed: ... Run shika wait.` line into the idle Lead's terminal, after a 1.5 second batch, only when the Lead is Ready or Waiting, the author has no unsent text there and has not typed for 3 seconds. It is a bracketed paste with a separate delayed Enter and counts as a submission, so the Lead shows Working. `shika pr` and `shika close` open the author's own Create PR and Close dialogs for a worker it started and block until the author answers (close is direct only where Close would not ask); the Lead never confirms, and selection and focus return to the Lead afterwards. The Lead itself has no diff stat, Create PR, shell tabs, or Changes. The Lead is a manager: it briefs workers fully, learns results from each worker's own `shika report` (a report-only token on its agent PTY, plus a prompt footer Shika adds at `new`), does a quick `diff --stat` check, and leaves quality to CI and the author; `read` and full `diff` are on demand. Read `docs/lead-agent.md` before modifying it; `docs/shika-cli.md` is the command and protocol reference; `docs/agent-activity.md` covers launch prompts.

Activity uses lifecycle reports where available (a session-local Shika extension for Pi), otherwise agent-specific live-screen chrome, never the user's scrollback. Working indicators survive silence; recognizable permission/question dialogs become Asking you. Ordinary text questions ending a response may be Ready to check. Two-second quiet is only a fallback inside an already-started turn, and bytes alone cannot start one. The elapsed timer belongs to the turn, not status changes: typing drafts, clicks, focus, scrolling, resize, active-turn Enter, and transient Ready/Working flicker do not reset it. It includes blocked time and is hidden outside Working. Notifications are titled `{project} - {task}` and route clicks to the matching card, once per turn at the first blocker or completion. Active and blocked turns both require safe-close confirmation. No global hook/config edits. Read `docs/agent-activity.md` before modifying this feature. Permission denial is reported in the app. On a card, the right end of the first line carries the status: moving pixels while Working, a grey dot while Waiting, an amber dot and tint while Asking, and a green dot plus the ready tint until a Ready result is seen. The status words are not painted on the card. Seen means its terminal has focus, or it stays selected for one second in the active window; passing over it with `j` does not count.

Ready cards show a diff stat such as `2 files +64 −3`, fetched in the background each time the card turns Ready and hidden on failure or with no changed files: `Core::session_diff_stat` compares the worktree to the merge base with the ref the card started from (its base branch), so it counts commits and uncommitted edits, plus untracked files that are not ignored. Close checks for own and unpushed commits against that same ref. If it no longer resolves, both use the default branch. Binary files count as files with no lines. Without either it falls back to HEAD, so only uncommitted work counts. It reads only, with `GIT_OPTIONAL_LOCKS=0`, and takes no core lock.

Changes panel: a read-only diff of the selected task right of the terminal, closed on every launch. Cmd+Option+B, its icon button, the View menu, or a click on a card's diff stat opens it focused; Escape or the toggle closes it and restores focus. It compares exactly as the diff stat does, fetches on open, card change, Ready, and `r`, and never watches or polls. It and the diff stat read only the task worktree (`GIT_CEILING_DIRECTORIES` plus a top-level check): a missing or broken `.git` is "Could not read changes", never the main checkout around `.worktrees/`. Huge files collapse, each row naming its cap; rows are virtualized and line columns are display width. No editing, staging, reverting, or syntax highlighting. 480px by default, 320 to 900; it yields width before the column. Read `docs/changes-panel.md` before modifying it.

`MANUAL_CHECKS.md` records integrated acceptance results and remaining checks. `crates/shika-terminal/MANUAL_CHECKS.md` records terminal-specific checks. Implementation and passing unit tests do not establish every GUI check.

Public code is MIT licensed. Bundled fonts retain their OFL licenses; copied icon notices are in `THIRD_PARTY_NOTICES.md` and ship in the app bundle. `design/DESIGN.md` is the visual spec. `design/Shika v3.dc.html` is an archived reference, not a standalone runnable demo. Runtime icons live in `assets/macos/`.

Confirmed publishing: Create PR in the terminal metadata row, Agent menu, or Cmd+Shift+P previews all non-ignored changes and an editable task-derived title, then stages, commits if needed, pushes, and creates a PR via authenticated `gh`. Target the task's recorded starting base, never the project's current base/default; missing or deleted bases require explicit selection. No merge, force-push, tests, or task cleanup. Busy/active turns block it; stale previews are refused. Partial success stays for retry; existing open PRs are reused. Afterwards the card shows that PR's checks as `#N` on its second line (ring, check, or a red cross with one "Checks failed" notification), read with `gh pr view` only while checks run or fail, plus a local `origin/<branch>` read every 10 seconds that restarts on a push. Read-only and memory only: no check lists, re-runs, or PRs opened outside Shika. Read `docs/publishing.md` before changing publishing and `docs/pr-checks.md` before changing the checks mark. Close still never commits.

Software updates: only the notarized release bundle embeds Sparkle 2, loaded at runtime from `Contents/Frameworks`; `cargo run` and `bundle-app.sh` bundles have no updater and no "Check for updates..." item. The feed `https://useshika.com/appcast.xml` redirects (`site/_redirects`) to the latest GitHub release's `appcast.xml`. The feed and the DMG are EdDSA signed with the key in the release Mac's keychain, and `CFBundleVersion` must rise every release. A lost key strands every installed copy. Read `docs/updates.md` before touching the updater, release scripts, feed, or keys.

## Using the app

`a` or Add project picks a git repo. A nested folder becomes the repo root. Cmd+N opens the CLI picker (`j` / `k`, number keys, Enter, Escape). It lists agents that are on the login-shell PATH and turned on in Settings, in Claude, Codex, Cursor CLI, Pi order. When none are available, Enter opens Settings on Agents. The new card is selected and the CLI starts in `<repo>/.worktrees/shika-draft-<id>`, after approval and setup when preparation is configured.

The column is 540px by default. Dragging its right edge resizes it (320 to 800px, the terminal keeps 420px), and a double-click on the edge restores 540px. A drag stops at the minimum and never hides the column. Cmd+B, the View menu, or the column icon button hides and shows it; hidden, the terminal fills the window and the button sits after the traffic lights. Cmd+Option+B shows or hides the Changes panel on the right; only its width persists. Hiding moves no focus, so `j` / `k` still change the agent on screen. Width and hidden state persist in `settings.json`. Its 48px top row is the title bar: traffic lights, the wordmark, the column toggle, the gear, and New agent; the terminal header fills the same row on the right, and empty space in both drags the window. The `+` on a project header, or its empty box, opens the picker for that project. A project's Remove appears when its header is hovered. The column has no summary: projects start under the top row.

`j` / `k` or the arrows move through every card and skip project headers. Every card is shown; the column scrolls when the list does not fit. An empty project is not a stop. Cmd+N opens the picker for the selected card's project, or the first project when nothing is selected, and Tab there changes the project. Clicking a card focuses its terminal, and so does clicking its notification. Right-click or Control-click a card opens Rename task `⌘⇧R` and Close task `⌘⇧W` at the pointer without selecting it; Close uses the clicked task's existing safe-close flow. Escape or an outside click dismisses and restores focus. No visible close control is added to cards. See `docs/keyboard-flow.md`. Enter does the same while the cards have focus. Ctrl+Q returns to the cards. Escape is typed into the terminal. Clicking a terminal tab focuses it. Cmd+T adds a shell, Cmd+W closes the selected shell and does nothing on the agent, and Ctrl+Tab / Ctrl+Shift+Tab cycle tabs. Cmd+1 through Cmd+9 jump to a tab, with the agent on Cmd+1. Each card retains its selected tab. Shell close stops its processes but leaves the task and worktree intact; Close task stops every owned PTY through the existing safe-close flow. Cmd+] / Cmd+[ move to the next/previous agent in row order, skipping project headers, wrapping, and keeping terminal focus when invoked there. Cmd+N opens New in the current project from either surface. Cmd+Shift+W closes the selected task from either surface. Cmd+B hides or shows the column. Cmd+Option+B opens the Changes panel focused, or closes it. These shortcuts do nothing while a dialog or picker is open. The Agent menu lists them; New, new shell, and shell close also have tooltips. Picker cancel, Settings dismissal, and Base branch completion or cancel restore the focus that opened them. Keyboard selection scrolls into view without pinning manual scrolling. Plain `n` and `c` do nothing. `b`, or a click on the branch after the project path, opens the Base branch dialog for the selected project.

New starts the task branch from the project's base branch: `origin/<base>`, else the local one, else New fails with "Base branch dev not found." With no base set it is `origin/HEAD`, then `main`, `master`, then the main checkout's HEAD. Opening the picker fetches that one branch from origin (never prompts, 4 second cap, failures ignored), and New waits for it. The worktree is created with `--no-track`, so a fresh card has no upstream. The picker footer names the base. In the dialog, branches already on this machine are listed under the field. Typing filters the list. Up and Down move through it, Enter applies the highlighted branch, and a typed name that is not listed is fetched from origin. Empty goes back to the default, and Escape cancels. Running cards keep the base they started from.

The shell is the user's login shell, with its cwd on the worktree. `git status` and `git diff` there are that task, not the main checkout. The author commits and pushes there.

Dropping a file (a screenshot thumbnail, an image from Finder) on the terminal pastes its escaped path and focuses that terminal. Claude Code and Cursor turn a pasted image path into an attachment. Ctrl-click or Cmd-click on a link in the terminal opens it.

Typing in the terminal, a text field, the picker, or the close dialog does not run the card keys. `docs/keyboard-flow.md` explains the Command flow layer, focus restoration, shell startup typeahead, selected-row scrolling, code map, and debugging checks for contributors.

Cmd-, (also the Shika menu and the gear in the top row of the column, left of New agent) opens Settings. Hovering the gear shows Settings ⌘,. The dialog has two sections, Appearance and Agents. `[` `]` or a click switches section, and `j` / `k` move inside the current one. Appearance sets the theme, then background opacity, blur radius, whether translucency covers the sidebar alone or the sidebar and terminal, the terminal font size, the branch prefix, and whether a notification plays a sound. Opacity is 0 to 100%, blur radius 0 to 255, and font size is 8 to 32 (default 14). The top rows are Theme (System, Light, or Dark), Light theme, and Dark theme. System follows macOS; Light and Dark force that side, including the traffic lights and menus, by setting `NSApp.appearance`. `j` / `k` choose a row. `h` / `l` or the arrows step the mode segment, step a theme pick through that side of `shika_terminal::catalog` (wrapping), step opacity and blur by 5, and font size by 1. Typing digits (or clicking the number) edits a value: Enter applies, Escape cancels the edit, and out-of-range values are clamped. A font size can include one decimal, such as 12.5. On the prefix row, Enter or a click edits the text, Enter applies, and Escape cancels. On the sound row, `h` turns the alert off and `l` turns it on. The banner still posts either way. Agents lists every CLI: its name, the binary path or "not found on PATH", and Off or On. `h` turns that agent off and `l` turns it on. Off stays off after the binary appears. A missing choice is on, so a later install shows up in New until it is turned off. Escape closes the dialog. Changes apply and save at once. At 100% opacity the window is opaque and blur does nothing. Below that, the column and resting cards frost, unless macOS Reduce transparency is on. The selected card, dialogs, picker, toast, and tooltips stay solid, because the blur only reaches what is behind the window and GPUI has no backdrop blur. When frost covers the terminal, its background follows the opacity down to a 20% floor, and CLI-colored cells stay opaque. The title bar uses the sidebar opacity, so the blur shows through it. Shika Light and Shika Dark chrome is hand-tuned in `appearance::chrome_for`; any other catalog theme derives its chrome from its palette and `ui`. The values and derivation rules are in `design/DESIGN.md`. The font size changes the terminal text. The chrome stays at its own sizes.

## Code

The Cargo workspace has three crates:

```
Cargo.toml              workspace, members crates/*
crates/shika-core/      projects.json, worktrees.json, settings.json, worktree add/remove,
                        login-shell PATH, agent presets, PTY processes and env, sessions.
                        No UI, no GPUI.
crates/shika-terminal/  alacritty_terminal wrapper and the GPUI terminal view. PTY bytes in,
                        input bytes and resizes out. Spawns no process.
crates/shika/           the GPUI app: window, cards, picker, close dialog, settings, toast,
                        keys, terminal tabs, translucency, .app bundle
```

`crates/shika-core/README.md` maps that crate (modules, lifecycles, invariants, tests). `docs/shika-cli.md` documents the Lead's `shika` command.

`assets/fonts/` holds JetBrains Mono and its OFL license. `assets/macos/` holds the bundle metadata and icon. `scripts/bundle-app.sh` builds a local ad hoc signed `.app`. `scripts/release-app.sh` builds on it to produce an arm64 `target/release/Shika.dmg`, Developer ID signed with the hardened runtime, notarized, and stapled; it needs the author's certificate and the `shika-notary` notarytool keychain profile, and stops when `assets/licenses/RUST_CRATES.txt` no longer matches `Cargo.lock` or the keychain's Sparkle key does not match `SUPublicEDKey`. It embeds Sparkle with `scripts/embed-sparkle.sh`; `scripts/appcast.sh notes.md` then writes the signed update feed. Run `scripts/update-notices.sh` (needs `cargo-about`) after changing dependencies and commit the result. `site/` is the static landing page; see `site/README.md`. Root `wrangler.jsonc` serves it through the Cloudflare Worker `shika` and enables PR previews with `previews: {}`. No site build step; Cloudflare build watch paths should include only `site/*` and `wrangler.jsonc`. Wrangler OAuth does not grant Workers Builds logs/settings access. Its demo is a sample-data prototype with CDN runtime dependencies. `docs/images/shika-native.png` is a native capture with disposable projects and simulated CLI output, not evidence of real-provider acceptance.

App data: `~/Library/Application Support/com.hieule.shika/`, the same directory used before the migration. `projects.json` and `worktrees.json` keep working there. `projects.json` holds each project's optional `baseBranch` and locally consented `approvedPreparation`; `worktrees.json` records each worktree's `baseRef`. `settings.json` holds `theme` (`mode` `system` / `light` / `dark`, and `light` / `dark` catalog ids), the appearance, the terminal font size, `branchPrefix`, `notificationSound`, `column` (`width`, `hidden`), `changes` (`width`), and `agents` (preset id to boolean; a missing id is on, and only explicit offs are written); a missing file or field takes the default (System with Shika Light and Shika Dark, opaque, 14, no prefix, sound on, a 540px column on screen, a 480px Changes panel, every agent on). An unknown or wrong-side theme id paints that side's Shika theme and stays saved until the user picks again. Sessions, titles, status, and PTY ids are memory only.

Worktrees live at `<repo>/.worktrees/<branch>`. `.worktrees/` is appended to that repo's `info/exclude`. Do not edit the user's `.gitignore` when the exclude file works.

Every PTY gets the login-shell `PATH`, `PWD` set to the worktree, and these variables removed so git cannot follow another checkout: `GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE`, `GIT_PREFIX`, `GIT_COMMON_DIR`, `GIT_OBJECT_DIRECTORY`.

## Toolchain

Cargo only. A fresh shell often has no `cargo`.

```sh
source "$HOME/.cargo/env"
```

GPUI needs full Xcode. The pinned platform dependency enables `runtime_shaders`, so contributors do not need the separate Metal Toolchain component to compile shaders during the build. Keep that feature unless a toolchain change is explicitly intended and verified. If Nix manages shell startup files such as `~/.zshenv`, use rustup's `--no-modify-path` option and configure Cargo's environment through the existing shell setup.

```sh
cargo test --workspace
cargo run -p shika
./scripts/bundle-app.sh --debug
open target/debug/Shika.app
```

`cargo run` inherits a terminal `PATH` and hides the Dock-launch bug. GUI apps do not see Homebrew, nvm, or `~/.local/bin`. `path_env` runs the login shell once at startup from a short `PATH`, with the environment cleared, because Nix's `__NIX_DARWIN_SET_ENVIRONMENT_DONE` stops a login shell from rebuilding `PATH`. Test discovery of CLIs installed outside the system PATH with a built `.app` opened with `open`, not only `cargo run`.

Claude Code saves no transcript, and so writes no session title, when it inherits `CLAUDE_CODE_CHILD_SESSION`. A Shika started with `cargo run` from inside a Claude Code session passes that variable to its PTYs, so branch titles fall back to the prompt there. Launch with `open` to test naming.

Preparation integration tests currently have a known parallel PID/timestamp temp-directory collision. `docs/worktree-preparation.md` records diagnosis and a serial workaround, not a fix; retain parallel workspace validation.

Never test against normal app data. Use disposable git repositories and local bare remotes, with `open -n target/debug/Shika.app --args --data-dir /absolute/test/data`. Before sending synthetic keystrokes, confirm Shika's own window is in front. Scratch GUI test hooks must hard-code a disposable Core data directory and use a unique bundle identifier: a repeated scratch-bundle launch has spawned a second instance without isolation arguments. Never let an instrumented binary fall back to normal app data. `--diagnostics-file /absolute/report` writes CLI discovery there, metadata-only native notification diagnostics to `/absolute/report.notifications`, and Changes panel read timings (no paths or content) to `/absolute/report.changes`.

Translucency uses GPUI's `Transparent` window background, not `Blurred`, because GPUI's blur has one fixed strength. The blur radius is set with the private `CGSSetWindowBackgroundBlurRadius` in `crates/shika/src/appearance.rs`, as Ghostty, WezTerm, and winit do. The terminal paints its default background with the configured alpha; its parent must not paint a second translucent fill under it.

No em dashes in code, docs, or visible text.
