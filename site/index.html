From prompt to pull request in five keys.

Start an agent, write the prompt, and move to the next one while it works. Your hands stay on the keyboard the whole way.

  1. ⌘N

    Start an agent

    Pick Claude Code, Codex, Cursor CLI, or Pi. Shika creates a worktree and starts the CLI inside it.

  2. ↵

    Write the prompt

    Type straight into the real terminal. The first line names the branch, then the CLI's own title renames it.

  3. ⌘]

    Move to the next one

    Jump to another agent while this one works. A notification names the task that is ready or needs an answer.

  4. ⌘T

    Review in a shell

    Open a shell in the same worktree. Read the diff, run the tests, try the app.

  5. ⌘⇧P

    Open the PR

    Preview every change and the title, then Shika commits, pushes, and opens the pull request with gh.

One git worktree per agent.

Agents never touch your main checkout or each other. Worktrees live in .worktrees/, kept out of git by the repo's local exclude, not your .gitignore.

~/code/routekit
├─ .worktrees/
│  ├─ fix-flaky-timeout-test
│  ├─ json-route-listing
│  └─ shika-draft-3f2a
└─ src/         untouched

Questions

The walkthrough is in the guide. Something else? Open an issue.

Is Shika really free?

Yes. It is MIT licensed, with no account and no paid tier. You pay your agent's provider the way you already do.

Which coding agents does it run?

Claude Code, Codex, Cursor CLI, and Pi. Shika starts the binary you already have, so your login, settings and plan come with it.

Will agents ask before running commands?

Shika's presets use the CLIs' automatic approval modes. Claude Code, Codex, and Cursor CLI bypass permission prompts or sandboxing; Pi starts with --approve. Agents can execute commands with your user account's access. A worktree separates Git edits but does not restrict access to files, credentials, or the network. Run agents only in projects you trust. Shika separately asks for approval before running configured worktree setup commands.

Does Shika send my code or prompts anywhere?

Shika has no telemetry or model API integration. Your agent CLI talks to its provider, Git fetch and push connect to your remotes, Create PR uses your GitHub CLI, and any worktree setup commands you approve can use the network. Your CLI controls what it sends to its provider.

Why a git worktree for every task?

So agents can edit the same repo at the same time without colliding, and your main checkout stays clean. Each worktree is a full checkout on its own branch, under .worktrees/ in your repo.

Will it commit or push for me?

Only when you ask. Create PR (⌘⇧P) shows every change and the title first, then commits, pushes, and opens the pull request. It never merges or force-pushes. Close never commits: with a clean tree and unpushed commits, it offers to push them.

What happens when I quit?

Your projects and worktrees stay on disk. Running sessions end, and the next launch lists leftover worktrees so you can clean them up when you choose.

Windows or Linux?

Not yet. Shika is a native Mac app for now.

Why the name?

After Shikamaru, the one who keeps track of everyone on the field while giving directions. Shika also means deer in Japanese, hence the logo.
