First session

Add a repo, start one agent, and leave it working while you look at another. The homepage prototype uses sample data if you want to press the keys before you install.

  1. a

    Add a project

    Pick a Git repository. A nested folder becomes the repo root. The column lists every project you add, and projects stay after you quit.

  2. ⌘N

    Start an agent

    Pick Claude Code, Codex, Cursor CLI, or Pi. Shika creates a branch and a worktree, then starts that CLI inside it. The picker footer names the base branch this task will start from.

  3. ↵

    Write the prompt

    With the cards focused, Enter moves the keys into the terminal. The first line of the prompt names the branch. About a second later, the CLI's own session title can rename that branch once. Pi does this only when a title was set. A branch already on a remote keeps its name.

  4. ⌘]⌘[

    Move to another task

    These work while you are typing in the terminal. ⌃Q returns to the cards, and then j and k, or the arrow keys, move through every card. Keys you type in the terminal stay with the CLI.

  5. Come back when it's ready

    A notification is titled with the project and the task. Click it to land on that card. Shika posts one per turn, the first time the agent asks or finishes.

  6. ⌘T

    Review in a shell

    The shell opens in that task's worktree. git status there is this task, not the main checkout. ⌘W closes the shell and leaves the agent running.

  7. ⌘⇧P

    Open the pull request

    Create PR shows the changes and a title you can edit, then commits, pushes, and opens the pull request. ⌘⇧W is Close, and it never commits. Both are below.

The presets start Claude Code, Codex, and Cursor CLI with approval bypassed, and Pi with --approve. Agents can run commands with your user account's access. A worktree separates Git edits. Files, credentials, and the network stay reachable. Run agents in a project you trust. Shika asks separately before it runs worktree setup commands.

Where the work lives

Each task is its own worktree under .worktrees/ in the repository. Agents can edit the same repo at the same time, and the main checkout stays as you left it. Shika lists .worktrees/ in the repository's .git/info/exclude, so git status on the main checkout skips it. Your .gitignore stays as it is.

The folder keeps the draft name it was created with. The branch starts as that name too. The first prompt renames the branch, and the CLI's session title can rename it once more. A prefix from Settings, if you set one, is added to those generated names.

New starts from the project's base branch. Shika uses origin/<base> when that ref exists, otherwise the local branch. With no base set, it uses origin/HEAD, then main, then master, then whatever the main checkout has checked out. Press b, or click the branch after the project path, to change it for the next task. A card keeps the base it started from. If that branch cannot be found, New stops and names it.

A new worktree has no upstream. Nothing is on the remote until you push.

While an agent works

The mark at the right of a card's first line is the status. The words are not written on the card.

  • Working. The agent has the turn. A time on the card is how long that turn has run.
  • Waiting. The session is up, and the first prompt has not been sent.
  • Asking. The agent is blocked on a question or a permission the screen shows. A plain question at the end of a reply can show as ready instead, so read the terminal when the card turns green.
  • Ready. The turn finished. When there are changes, the card adds a diff stat such as 2 files +64 −3.

One terminal is on screen. The others keep running, including while you look at another card, so a busy CLI does not stall. The agent is the first tab. ⌘1 through ⌘9 jump to a tab, and ⌃Tab cycles them.

Drop a file on the terminal to paste its path. Claude Code and Cursor turn an image path into an attachment. Control-click or Command-click a link in the terminal to open it.

Review and ship

Click the diff stat, or press ⌘⌥B, to open Changes on the right. It starts closed. The panel is a read-only diff of this worktree against the base the task started from, including commits and uncommitted files that are not ignored. With the panel focused, j and k scroll, and r refreshes. Escape closes it and puts focus back. Nothing in the panel stages, edits, or reverts.

Create PR is ⌘⇧P. It is also in the terminal's metadata row and the Agent menu. You see every non-ignored change and a title you can edit. Confirm, and Shika stages, commits if something is still uncommitted, pushes, and opens a pull request with gh. The pull request targets the base the task started from. If that base is gone, Shika asks you to pick one. It never merges or force-pushes. An open pull request for the branch is reused. You need the GitHub CLI, signed in. Shika waits while the agent is working or asking. If a later step fails, the work stays so you can run it again.

Afterward the card shows that pull request's number, and whether its checks are running, passing, or failing.

You can commit and push yourself in a shell tab. That push leaves the card open. You close the card.

Rename the task

Right-click a card and choose Rename task, or press ⌘⇧R. The new name is what the card shows, what later notifications use, and what the next Create PR title starts as. The Git branch, the worktree folder, existing commits, and an existing pull request keep their names. A name you set stays put when a later prompt or CLI title arrives. That prompt or title can still name the branch.

The name lasts for this session. Quit does not bring live sessions back, so the card name goes with them. The branch and the worktree stay on disk.

Close and quit

⌘⇧W closes the selected task, from the cards or the terminal. Right-click a card and choose Close task to close that one, even when another card is selected.

Close asks before it throws away uncommitted work or commits that are not on the base. When the tree is clean and those commits are unpushed, it can push them. Close never commits. A clean task that is already published closes without a question.

Quit ends the live sessions. Projects remain. Worktrees remain on disk, and the next launch lists leftovers so you can remove them when you choose.

If you switched branches inside the worktree, and both the recorded branch and the current one are clean and already published, Close can remove the worktree and leave both local branches. Dirty work, unpublished commits, a missing ref, or a detached HEAD stay in place.

Keyboard

These do nothing while a dialog or the picker is open. Typing in the terminal, a text field, or the close dialog does not run the card keys.

Prepare a worktree

Optional. To install dependencies or copy local files before the CLI starts, add .shika/worktrees.json to the project's main checkout. Use that project's own commands.

.shika/worktrees.json
{
  "copy-files": [".env.local"],
  "setup-worktree": ["npm ci"],
  "timeout-seconds": 600
}

Shika asks the first time, and again when the parsed file changes. Copy and setup finish before the CLI starts. Their output is in the task's terminal, and you can cancel. Copied files have to already be ignored by Git on the main checkout and on the task's base. The commands run as you, with your account's access, and they need to finish rather than stay running in the background. The timeout is 600 seconds unless the file sets another.

If setup fails before the worktree has changed, Shika removes it. If the worktree may have changed, it stays for you to clean up.

Settings

⌘,, the gear, or the Shika menu. Theme follows the system, or you can force light or dark. Opacity, blur, and whether the frost covers the sidebar alone or the terminal too. Terminal font size. A branch prefix for names Shika generates. Whether a notification plays the system alert sound. The banner still posts when the sound is off. Changes apply and save at once.

The signed app checks for updates from Shika, then Check for updates. A copy you build yourself has no updater.

If a step you needed is missing from this guide, open an issue. That is how a new section starts.
