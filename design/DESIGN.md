# Shika design system

Shika is a keyboard-first Mac app for running a few coding agents at once. It is named for Shikamaru: the one who keeps track of everyone on the field while you give directions. Shika creates a git worktree per task, starts the CLI the user already uses (Claude Code, Codex, Cursor CLI, Pi) in a real PTY, and notifies them when an agent needs attention or finishes a turn. Closing the task removes its worktree after the safe-close checks. A push keeps the task open. Kiro is planned.

The user is a developer who does not watch agents work. They start a task, go to the browser, and come back on a notification. The UI is built around that: a wide column for tracking agents, a smaller terminal for the moments they need to read or answer, and, only when asked for, a read-only Changes panel for a quick look at what a turn changed.

**Sources**
- `design/Shika v3.dc.html`: the archived visual reference. Its original runtime and styles are not included beside it, so it is not a standalone runnable page. The browser demo lives in `site/demo/` and uses sample data; the native app and this written spec define current behavior.
- Logo artwork: `design/assets/shika-logo.png`.

**Publishing.** Create PR is a neutral text control in the terminal metadata row, using its existing 11.5px text, 6px radius, terminal colors and hover wash, with tooltip "Commit, push, create PR ⌘⇧P". The Agent menu exposes the same action. Its 400px confirmation dialog reuses dialog tokens, 360px mono text fields, selectable branch list rows, and scrollable file names capped at the existing base-list height. Title "Create PR?", facts name repository/source/target and all changed files, labels "Commit and PR title" and "PR target", Cancel `esc`, and primary "Commit, push, create PR" `↵` ("Publishing..." while busy). Tab switches fields, Enter confirms, Escape cancels. Missing recorded targets ask for explicit selection. Errors stay in the dialog; completion restores focus and opens the PR URL. No new color, size, or animation tokens. See `docs/publishing.md`.

**Changes.** The read-only Changes panel right of the terminal is specified under Changes panel below, its diff colors under Color. Behavior, refresh, and caps are in `docs/changes-panel.md`.

**Glass.** Opacity, blur, and whether frost covers the sidebar alone or the sidebar and terminal: `crates/shika/src/appearance.rs`, saved by `crates/shika-core/src/settings.rs`. The values are under Glass below. There is no `tokens/glass.css`.

## Content fundamentals

Shika talks like a terse colleague. It reports facts and names consequences. It does not cheer, apologize, or explain itself.

- **Sentence case everywhere.** Buttons, titles, statuses: "New agent", "Ready to check", "Delete worktree". The only all-caps text is "SHIKA" in the notification header, matching macOS.
- **Status words are fixed:** Ready to check, Working, Waiting, Asking you. They name the states and are not painted on the card. Asking you is a recognizable blocking permission/question dialog, not a semantic guess from prose. Never invent synonyms ("Needs input", "Done").
- **Address the user as "you", rarely.** "Asking you". Shika never says "I" or "we".
- **Buttons are verbs naming the outcome:** "Delete worktree", not "OK" or "Yes". Cancel is "Cancel".
- **Confirm dialogs ask a question about the specific task**, then list the facts: "Close “Fix flaky resize test”?" / "The worktree has 2 uncommitted files: src/cli.rs, src/layout.rs." / "This stops the session and force-removes .worktrees/fix-flaky-resize-test."
- **Branch-switch close** uses the existing close dialog shell and tokens: "Close “{task}” after branch switch?", recorded/current branch facts in mono, publication and branch-preservation facts, and an active-agent warning when applicable. Cancel `esc` and the primary Close task `↵` are the only choices. Unsafe recovery shows an error instead of offering destructive actions. Both local branches stay; no ownership transfer. See `docs/branch-switch-close.md`.
- **Toasts are past tense, one sentence:** "Pushed fix-flaky-resize-test. Card and worktree removed."
- **Errors state the cause plainly:** "kiro not found on PATH". No "Oops".
- **Use real developer nouns:** branch, worktree, PATH, push. Branch names and paths are always in mono.
- **Key hints are lowercase verbs:** move, new, terminal, shell, close.
- **No emoji. No exclamation marks. No marketing copy inside the app.**
- Card titles start with the user's prompt, then the CLI's own title, shortened; a manual task name takes priority. Before the prompt is sent the card reads "New Claude Code" (or whichever CLI), unless manually named.

## Visual foundations

Names such as `--ink-1` and `--surface-app` are how this document talks about color, type, and space. The app implements them as GPUI values in the files in the Index. Do not add a CSS file beside them.

**Overall feel.** A quiet Mac app in the spirit of Obsidian and the Codex app: warm neutrals, system font, hairlines instead of boxes, and almost no color. The default themes are Shika Light (sage-tinted paper) and Shika Dark (warm charcoal), following the system appearance. Settings can pick another light and dark theme from the catalog, and can force light or dark. The agent column and the terminal share one background, split by the column's hairline. The only hues are the four status colors, so anything colored on screen means "look here". The one exception is the code surface of the Changes panel, where added and removed lines take the terminal palette's green and red, as a CLI would paint them in the terminal beside it.

**Color.**
- Neutrals carry a faint sage tint taken from the logo (hue ~120, very low chroma). Light: ink `#262824` on column `#F1F2EC`, raised `#FFFFFF`. Dark: ink `#E8EBE3` on column `#1A1C19`, raised `#272A25`.
- Brand tokens (`--brand-ink`, `--brand-sage`, `--brand-cream`, `--brand-mint`, `--brand-tile`) come from the logo and are for the logo, icon and wordmark only, never UI chrome.
- Status is the only color: amber = asking you, green = ready to check, blue = working, grey = waiting. Red is reserved for failed PR checks, and colors only the PR mark. Each has three tokens: `dot`, `text` (meets contrast on the column), `tint` (resting background for asking and ready cards only).
- There is **no brand accent**. Selection and focus use ink (`--focus-ring`), not blue. Primary buttons are ink-filled.
- **Themes.** Shika Light and Shika Dark are hand-tuned: the values in this file. Every other catalog theme derives each `Chrome` field from its palette and `ui` (`derived_chrome` in `crates/shika/src/appearance.rs`), so it looks like that theme with Shika's layout and hierarchy:
  - Its background is the column and the terminal, solid and in glass. `ui.surface` is the selected card, raised controls, dialogs, and the picker; resting cards are that surface at 40%. `ui.mantle` is the solid terminal header, key caps, and sunken tracks. Without `ui`, the surface is a step toward white (light) or the foreground (dark), and the mantle a step toward the frame.
  - `--ink-1` is the foreground. `--ink-3` is `ui.muted`, or the foreground 42% of the way to the background, pushed until it meets 4.5:1 on the column. `--ink-2` is halfway between them; `--ink-4` and `--ink-5` fade `--ink-3` 33% and 65% toward the background.
  - Lines, washes, and rings are the foreground at a low alpha, as on Shika's glass, so they work over glass.
  - Status: ready is ANSI green, asking ANSI yellow, working ANSI blue, waiting the `--ink-4` grey. The dot is the ANSI color. Text darkens it toward black (lightens toward white on a dark theme) until it meets 4.5:1 on the column, which keeps the hue. Ready and asking tints mix the hue 12% (dark 10%) into the background, at the Shika glass alphas when frosted.
  - The primary button is the foreground with background text. The toast is inverted the same way. Popups stay solid.
  - The terminal header follows the same rules as Shika's: a step (the mantle) when solid; in frost it keeps the terminal's color and the step is its alpha.
- **Diff colors.** Only inside the Changes panel's rows (diff lines and the file header counts), never in chrome. Added is the active terminal palette's ANSI green (ANSI 2), removed its ANSI red (ANSI 1). A tint is the terminal background mixed toward the hue, 8% on a light theme and 10% on a dark one, and it is opaque, like a CLI-colored cell in the terminal. The text is the ANSI color, darkened toward black (lightened toward white on a dark theme) until it meets 4.5:1 on its tint, which keeps the hue: the same rule as derived status text. Every theme derives them this way in `chrome_for`; Shika's results are: Light added tint `#E3E8DE` text `#3A7439`, removed `#ECE4DE` / `#AE4539`; Light glass added `#E7EEE3` / `#3B763A`, removed `#F1EAE3` / `#B2463A`; Dark added `#252D24` / `#8CC98A`, removed `#2E2521` / `#E0786B`; Dark glass added `#242C23` / `#8CC98A`, removed `#2C231F` / `#E0786B`.
- The terminal takes the theme's background and a soft ANSI 16 (`--ansi-*`). Shika Light's normal ANSI colors meet 4.5:1 on its background, and its bold text keeps its color instead of switching to the lighter bright set. The terminal header is a step darker than the terminal when solid (`#151714` dark, `#E7E9E1` light); in frost it keeps the terminal's color and the step is its alpha. Terminal-side lines and washes are translucent ink: white in dark, black in light.

**Type.**
- Two families. UI: the macOS system font (SF Pro) via `-apple-system`. Code, paths, branches, timers, key caps and the terminal: JetBrains Mono.
- Exact sizes, not a grid: 15 / 14 / 13.5 / 13 / 12.5 / 12 / 11.5 / 11 / 10.5. Weights 400, 500, 600 only.
- Timers use `tabular-nums` so they don't jitter.
- Anything a developer might copy (branch, path, command) is mono.

**Layout.**
- Agent column 540px by default, terminal takes the rest. One terminal on screen, ever. The Changes panel, when open, sits right of the terminal (`[column][terminal][panel]`); it is a read-only diff, not a second terminal. The window opens at 1400x880 and stops at 960x600.
- The column's right edge resizes it: an invisible 8px strip centered on the hairline, with the resize cursor. On hover and through a drag a 2px ink-4 line shows in the strip. Width 320 to 800; the terminal keeps at least 420. Double-click restores 540. A drag stops at 320 and never hides the column; only the toggle does.
- The column can hide (Cmd+B). Its toggle is a 24px icon button (radius 6, 15px glyph: a window with its left pane split off, drawn for Shika) before the gear, ink-3, ink-1 on hover, tooltip "Hide agent column ⌘B". Hidden, the terminal header starts with the same button after the traffic lights (at the wordmark's inset, centered in the 48px row) in term-dim, term-white and the term-hover wash on hover, tooltip "Show agent column ⌘B"; over the empty state it sits in the drag strip. Below 420px (580px with Leftover worktrees) the footer drops its key hints. On a card's second line the branch truncates before the diff stat.
- The 48px top row of both halves is the title bar; there is no separate title strip. Column half: the real traffic lights (x 18, centered), the wordmark "Shika" (13.5 semibold), a gear icon button (24px, radius 6, 15px glyph, tooltip "Settings ⌘,"), and New agent `⌘N`. Terminal half: the terminal header, or a plain strip over the empty state. Empty space in both halves drags the window and a double-click zooms.
- No summary: the project list starts right under the top row. Status lives on the cards.
- Project list (padding 8 12 18, 20 between projects, 6 inside). Header (min height 24, padding 0 4 0 8, gap 10): name 15 semibold, path mono 12 ink-3 with `~`, the base branch New starts from (`dev`, or `main` when unset) in mono 12 ink-3 after a 12px git-branch glyph (gap 4), both turning ink-1 on hover and shows the tooltip "Base branch b" (it is hidden while unresolved or when the configured branch is missing), "2 agents" 11.5 ink-3, then `+` (24px icon button, opens the picker for that project). The path truncates first. A click on the base branch, or `b`, opens the Base branch dialog. Remove shows only while the header is hovered. A selected header gets the row-selected wash, radius 6. `j`/`k` moves through cards and skips headers. Every card is shown. The list scrolls when it does not fit.
- Empty project: 1px dashed box, radius 10, padding 12 14, 12.5 ink-3, "No one is on this repo. Press + to start an agent." A click opens the picker for that project.
- Footer (top line-2, padding 10 12 12): "Add project…" `a` (12.5 ink-2, hover wash, radius 6), "Leftover worktrees (N)" when there are leftovers, and on the right `⌘] ⌘[` move, `⌘⇧W` close (11 ink-3). The hints stay on that one line.
- Terminal header (48px, term-header fill, bottom term-line): connected, task-scoped terminal tabs, not a segmented control. Tabs sit on the bottom of the row, 34 high, radius 7 on the top corners only, padding 0 12, 12px, min 88 and max 180 wide with the label truncated, no gap between them, starting 8px from the left so the label lines up with the terminal text. The active tab is filled with term-tab, has a 1px term-line outline on its top and sides, and term-white text; at the bottom its sides flare outward in concave curves of radius 7 that run into the bottom line, which breaks under it, so the tab opens into the terminal. The flares are painted over the bottom corners of the neighbors, so labels do not move when the active tab changes; a neighbor's bottom line stops where a flare meets it, and the strip keeps 7px after the last tab for its flare. term-tab is the terminal background adjusted so that, painted over the translucent header, it gives exactly the terminal's pixels. Inactive tabs are term-dim text with no fill; hover gives term-fg text and fills the tab's own shape with the term-hover wash: the same top, sides, and flares, standing on the bottom line instead of breaking it, with no outline. Beside the active tab, the hover's bottom corner on that side rounds inward (radius 7) and fits inside the active tab's flare. Only the pinned CLI tab exists initially. Shell tabs are added on request and numbered monotonically (Shell, Shell 2). Each shell has a 16px `×` (radius 4, hover term-hover and term-white, tooltip "Close shell tab (stops its processes) ⌘W"), always shown on the active tab and on hover otherwise, in a fixed slot so the label does not move. The CLI tab has no `×`. `+` (24px, radius 6, 15px glyph, tooltip "New shell tab ⌘T") follows the last tab; when tabs overflow, the strip scrolls and `+` stays at its right edge. Close task `⌘⇧W` (1px term-seg-active border, radius 6, hover term-hover) stays at the right, centered on the tab labels. The bottom line is drawn by each piece of the row, never by the header, since a translucent tab cannot hide a line under it. Selection reveals the tab without pinning manual scrolling. A metadata row below the header (padding 8 20 2, gap 12) shares the terminal background, as part of the active tab's page: the worktree path in mono 11.5 term-dim, `~` for home, ellipsis at the start; the focus hint is 11.5 term-faint-ui, "↵ type here" or "ctrl q back to cards".
- Empty terminal: the app icon 64px, "No agent selected" 13 term-faint-ui, and `j` select, `⌘N` new agent. The toast sits centered over the terminal side, 22 from the bottom.
- Projects stay visible even with no agents, shown as a dashed empty box.
- Cards inside a project are sorted by attention: asking, ready, working, waiting. A project's Lead card is always first.
- The Changes panel's layout, rows, and empty states are under Changes panel below.

**Cards.** Radius 10, padding 12/14/11, gap 6. Line one: the task in 14 medium (line 20, ink-3 while it still reads "New <CLI>"), then, gap 10, the elapsed turn time in mono 11.5 in the working text color, shown only while Working (`42s`, `51m`, `1h 3m`), including blocked time and never reset by drafts, terminal interactions, or status flicker, and the status signal at the right end, a 13px slot so signals line up down the column. Working: three 3px squares in the working dot color, gap 2, rising up to 5px in a staggered wave, offsets snapped to whole points. Ready: an 8px ready dot until the result is seen. Asking: an 8px amber dot, including after the blocker was seen. Waiting: an 8px solid dot in the waiting ring grey. A seen Ready card shows nothing there. There is no dot on the left; the eye reads to the right. A Ready result is seen when its terminal has focus, or when the card stays selected for one second while the window is active, so `j` passing over it does not count. Each turn that ends brings the dot back. Line two (no indent, 12px ink-3, gap 6, `·` in ink-5): CLI · branch (mono 11.5, truncates before the diff stat) · the diff stat while Ready, like `2 files +64 −3` with a real minus · after Create PR, the PR mark: `#42` in mono 11.5, gap 4, then a 7px ink-4 ring while checks run, `✓` when they pass, or `✗` when one fails, the whole mark in the failed text color and medium weight then; ink-3 otherwise, and the number alone when the repository reports no checks. The mark never truncates, has no hover color, and a click opens the PR without focusing the terminal; its tooltip is "Checks running", "Checks passed", "Checks failed", or "Open PR". The diff stat is a click target: pointer cursor, ink-1 on hover, tooltip "Show changes ⌥⌘B"; a click selects the card and opens the Changes panel focused. Status on a card is the signal, the tint, the timer, the diff stat, and the PR mark. A failed mark adds no tint and does not change the card order. While setup is running or has failed, the stage or "Setup failed" sits between the CLI and the branch in the status text color (600 Ready/Asking, 500 Working, 400 Waiting). A long setup stage gives way; "Setup failed" stays whole. The status words are not painted on the card. The selected card shows key hints on the right while the cards have focus: Ready `↵ read`, Asking `↵ answer`, Working `↵ watch`, Waiting `↵ write prompt`. Key caps everywhere: mono 10.5, sunken fill, ink-2, radius 4, padding 1 5 (0 5 inside a card). No agent output on cards. At rest: 45% white (3% white in dark) with a 1px hairline (`--shadow-card`). Asking and unseen ready cards get a faint status tint. Selected: raised white with a 1.5px ink outline. Selected while the terminal has focus: hairline only, hints hidden.

**Lead card and worker marker.** A project's Lead is an ordinary card (same signal, tint, timer, selection, and hints) with three differences. Its task reads "Lead" in ink-1. Line two reads the CLI, then "Project lead" in ink-2 medium where other cards show the branch: a Lead has no branch, so it also has no diff stat, PR mark, Create PR button, or `+` shell tab, and the Changes panel says "The Lead does not change files". A worker that a Lead started reads the CLI, then "from Lead" in ink-4, then its branch as usual. No new color, icon, or weight; both marks are plain text in existing inks. The picker started with `⌘L` (Agent > New Lead…) is the same 420px picker titled "New Lead", with the footer "reads a checkout of `dev`" (the base in mono) in place of "branches from". The close dialog for a Lead says "Discard stops the Lead and deletes its worktree. Its workers stay as ordinary cards." and offers no Push. See `docs/lead-agent.md`.

**Card context menu.** Right-click or Control-click a card opens a menu at the pointer without selecting it or entering its terminal. Items are Rename task… with `⌘⇧R`, then Close task with `⌘⇧W`. Rename is ink-4 and disabled until the CLI session exists. The highlighted item uses the row-selected wash; Up/Down, `j`/`k`, Tab, and hover change it; Enter activates it. Live cards start on Rename, other cards on Close. Reuse the solid `dialog_shell` surface, ring, shadow, and 12px radius, with 8px padding and content-sized width; the item uses `list_row`'s 13/19 type, 8/10 padding, 7px radius, and `row_selected` hover wash, with a 20px gap before the key cap. Snap inside the window with the picker's 8px margin. No backdrop tint, new icon, permanent close control, or animation. Escape or an outside click dismisses and restores focus; activation uses the existing safe-close flow for the clicked task. `⌘⇧W` always activates Close; `⌘⇧R` activates Rename. See `docs/keyboard-flow.md`.

**Rename task.** Also in the Agent menu and on `⌘⇧R`, it reuses the 400px dialog and existing tokens: title "Rename task", the fact "Changes the task name and future Create PR defaults. The branch and worktree stay unchanged.", and a 360px native text field using the existing 26px height, 6px radius, 8px inset, mono 12px type, 16px line height, raised fill, and focus/line-control border. The full name starts selected; selection uses row-selected, the caret is 1px focus ink, and composing text is underlined in ink. Long names scroll inside the field, never stretch the dialog. Errors use dialog text. Buttons are Cancel `esc` and primary Rename task `↵`. Apply/cancel preserves selection and restores opening focus. No new animation or color. Behavior and FAQ: `docs/task-names.md`.

**Changes panel.** A read-only diff of the selected task, right of the terminal, closed by default and on every launch. Behavior is in `docs/changes-panel.md`.
- **Width.** 480px by default, 320 to 900, saved as `changes.width` in `settings.json`; whether it is open is not saved. Its left edge is a 1px term-line hairline, full height, through the title row. The resize strip mirrors the column's: an invisible 8px strip centered on the hairline, the resize cursor, and a 2px ink-4 line on hover and through a drag. Double-click restores 480. A drag stops at 320, and at the width that would leave the terminal under 420; it never closes the panel and never moves the column.
- **Narrow windows.** The terminal keeps 420. The panel gives way first, down to 320, then the column, down to 320. Only when both are at 320 does the terminal go under 420 (a 960px window with the column and the panel shows a 320px terminal); Cmd+B gives the column's width back. Growing the window brings the saved widths back.
- **Motion.** The panel opens and closes at once, with no width animation: each animated frame would resize the terminal's PTY.
- **Title row.** 48px and part of the title bar, painted like the terminal header: term-header fill, a bottom term-line, solid a step darker, in frost the terminal's color at the header's alpha. Its content is centered on the same 34px band as the tab labels at the bottom of the row, so it lines up with the tabs and Close task. Padding 0 12 0 20, gap 10: "Changes" 13 medium (term-white while the panel has focus, term-fg otherwise), the diff stat 12 term-dim (`2 files +64 −3`, `model::diff_stat_label`, hidden when nothing is counted), then, while the panel has focus, the hints `r` refresh and `esc` close (11.5 term-faint-ui, key caps on term-line with term-dim text, gap 12; dropped when the panel is narrower than 420), and the toggle at the right end. The stat truncates before the toggle. Empty space drags the window and a double-click zooms.
- **Toggle.** A 24px icon button, radius 6, 15px glyph (`CHANGES_ICON`: the column icon mirrored, a window with its right pane split off, drawn for Shika), term-dim, term-white with the term-hover wash on hover. Closed, it sits at the right end of the terminal header, 8 after Close task and 12 from the window's right edge, centered on the tab labels, tooltip "Show changes ⌥⌘B"; over the empty terminal it sits at the same place in the plain strip. Open, it is the last thing in the panel's title row, tooltip "Hide changes ⌥⌘B". Both places are 12 from the right edge on the same band, so the button does not move when pressed.
- **Background.** The list sits on term-surface and follows the terminal's translucency: opaque when frost covers the sidebar alone; the terminal's alpha (the Settings opacity, floor 0.2) when frost covers the terminal. The panel paints that one fill; rows paint only their opaque tints, never a second translucent fill.
- **Rows.** One height for every row, the terminal's row height (font size × 1.52, rounded: 21 at 14), so the list is uniform and virtualized. Row text is JetBrains Mono at the terminal font size; the title row keeps chrome sizes. The list starts 8 under the title row and ends 28 after the last row (the terminal's bottom pad). Content is inset 20 left and right; tints span the full panel width.
  - File header: an empty row before it (not before the first file), then the header with a 1px term-line rule along its top edge, full width (not on the first file, which already sits under the title row's line). The status letter (A added, M modified, D deleted, R renamed, U untracked) in term-dim, one cell, then the path in term-white, `old → new` for a rename with the arrow in term-dim, truncated at the start so the file name stays. At the right, `+64` in diff-added text and `−3` (real minus) in diff-removed text, one cell apart, on no tint; both are left out when zero (binary, mode-only, and empty files).
  - Hunk header: the whole `@@ -12,7 +12,9 @@ fn resize` line in term-dim, starting where the line numbers start, truncated at the end.
  - Diff line: the line number right-aligned in a gutter as wide as the widest number in the diff, at least 4 cells, in term-dim; one cell; the sign (`+`, `-`, or a space) in the line's color; one cell; the text. The number is the new line number, the old one for a removed line. Tabs expand to 4-column stops; columns are display width, so CJK and most emoji take two cells and combining marks none, and a wide character cut by the left edge shows its visible half as a blank cell; control characters show as their Unicode control pictures (`␛`), and C1 controls and bidirectional overrides as `�`; a CRLF line's `\r` is not shown. Context text is the palette foreground on no tint. Added lines are diff-added text on the diff-added tint, removed lines the same in red, the tint across the full row.
  - `\ No newline at end of file`: term-dim, no number.
  - A binary file's header is followed by one row "Binary file" in term-dim. A mode-only change is its header alone.
  - Collapsed file: one row in term-dim worded for the cap that collapsed it. Over its own line cap, "Large diff hidden - 4,812 lines" ("1 line" for one). Over its own size cap with few lines, "Large file hidden - 3.2 MB" for an untracked file and "Large diff hidden - 6.3 MB" for a tracked one (decimal units, one decimal). Small but past the task's total budget, "Diff hidden - 12 lines", never "Large". Then the key cap `o` (on term-line, term-dim text) and "show" in 11.5 term-faint-ui; pointer cursor and the term-hover wash on hover. A click or `o` expands it.
  - An expanded file past core's hard limit ends with one row "4,812 lines not shown" in term-dim.
- **Long lines.** No wrapping. Line text scrolls horizontally by one offset shared by every row, smoothly by pixel with the trackpad and 8 columns per `h`/`l`; the gutter, file headers, and hunk headers stay put and truncate instead. Text clips 20 from the right edge. Tints always span the visible width.
- **Focus.** No text cursor, no selection, and no focus ring. Focus shows in the title row ("Changes" in term-white and the hints) and, as when the terminal has focus, the selected card drops to its hairline and the terminal cursor is a hollow block.
- **Empty states.** Centered in the list area, 13 term-faint-ui, the empty terminal's line: "No changes" for a clean task, "No agent selected", "Preparing worktree" while setup runs, and "Setup failed" when setup failed and the card has no worktree to read. On a git failure, "Could not read changes", and under it (gap 6) the first error line in mono 11.5 term-faint, truncated at the end. While the first read for a newly shown card is pending the list is blank; after 500ms with nothing, "Reading changes" appears in the same style.
- **Overlays.** Dialogs and the picker stay centered in the window; the toast stays centered over the terminal, not the panel.

**Borders and elevation.** Hairlines everywhere (`rgba(0,0,0,.045)` or `#DEDBD5`). Real drop shadows only on floating things: dialogs, picker, toast, notification. Buttons have a 1px shadow in light mode only.

**Corner radii.** 4 key caps and shell `×` · 5 segments · 6 icon buttons, text buttons, fields, Close · 7 buttons, list rows, segment tracks, terminal tab tops and flares · 8 toasts · 10 cards · 12 dialogs · 14 notifications. Inner radii nest: segment 5 inside track 7 with 2px padding.

**Overlays.** The picker is 420px with padding 8 and sits 18% from the top: "New agent" 14 semibold, "in {project}" 13 ink-3, "tab to change project" 11.5 ink-4; rows (padding 8 10, radius 7, gap 12) with a number key cap, the CLI name 13.5 medium (ink-4 when missing), and the binary path or "<binary> not found on PATH" in mono 11 ink-3 on the right; a footer under line-2: "↵ start", "esc cancel", "branches from `dev`" with the base branch in mono (gap 4), or "creates a branch and a worktree" while the base is unknown. Dialogs are 400px (Settings 440), padding 20 20 16, gap 8, 20% from the top: title 14 semibold, facts 13/19 ink-2, buttons right-aligned with gap 8. Secondary buttons: raised fill, 1px line-control border, radius 7, 12.5px, the control shadow in light only, raised-hover on hover, the key in mono ink-3 after the label. The primary button is ink-filled with the key in `--kbd-inverse-fg`; in the close dialog it is Push when Push is offered, otherwise Discard. The Base branch dialog is a 400px dialog: "Base branch for {project}", the fact "New agents branch from it. Running agents keep their base.", a 360px mono field (the Settings text field: 26 high, radius 6, raised fill, focus border, 1px focus caret) prefilled with the saved branch, or empty with the default branch as an ink-4 placeholder; under the field, known branches in list rows (mono 12, radius 7, at most six visible and then scrolling), filtered to names starting with the field, the highlighted row in the row-selected wash, and "checked out" in ink-3 on the main checkout's branch; Up and Down move the highlight, and a click sets that branch; when the typed name matches nothing and origin exists, ink-3 dialog text reads "Not on this machine. Enter fetches it from origin."; an error under it in dialog text and ink-1, such as "No branch named dev on origin or locally."; then Cancel `esc` and the primary "Set base branch" `↵`, which reads "Use default branch" while the field is empty and no row is highlighted. Settings rows are 13px list rows with mono number fields, `-`/`+` as small secondary buttons, and "Apply to" as a segmented control on a sunken track with a raised active segment. The first three rows are the theme: "Theme" (a segmented control: System, Light, Dark), then "Light theme" and "Dark theme", each the theme's name in a 168px field in the system font between `-` and `+`, truncating if long. On those rows `h`/`l` step to the previous or next theme of that side in catalog order, wrapping, and on the Theme row they step the segment; their hints are `h l` theme and `h l` mode. A change paints and saves at once, so a pick previews live when its side is showing. When a short window makes the panel scroll, `j`/`k` keep the selected row in view. The labels carry the meaning ("Terminal font size"); there is no help paragraph, only the key hints for the selected row above Done.

**Backgrounds.** No gradients, images, textures, or illustrations. At 100% opacity the fills are flat. Below that, the window is glass, described next. The macOS notification may blur to match the OS.

**Motion.** Short and functional. Hover/press 120ms, overlays fade up 4px in 180ms, column width changes in 220ms, all on `cubic-bezier(.2,.8,.2,1)`. The Changes panel opens and closes at once, since its width resizes the PTY. The only loops: the working pixels wave (1.2s, each square a sixth of a cycle behind the last) and the terminal cursor blinks (1.1s, steps). Nothing else bounces. Keep the pixels small: Working is the state that does not need the user. `prefers-reduced-motion` zeroes durations.

**Hover and press.** Hover adds a 4% ink wash (`--surface-hover`) or steps the surface lighter (`--surface-raised-hover`). Icon buttons darken their glyph from ink-3 to ink-1. There is no press scale. Cards have no hover; selection is the state that matters.

**Focus model.** Focus is on the cards, in the terminal, or in the Changes panel while it is open. Clicking a card selects it and focuses its terminal, as does clicking its notification, so the next keystroke is typed there. `j`/`k` still moves through cards only while the cards have focus. Cards focused: selected card has the ink outline and key hints; terminal cursor is a hollow block. Terminal focused: card outline drops to a hairline; cursor is a solid blinking block; the terminal header reads "ctrl q back to cards". Escape is typed into the terminal. Command shortcuts provide direct transitions from either surface: `⌘]` / `⌘[` move between agents while preserving card versus terminal focus, `⌘N` opens New in the current project, `⌘⇧W` closes the selected task, `⌘B` hides or shows the agent column without moving focus, and `⌥⌘B` opens the Changes panel focused or closes it. Closing it from inside restores the focus that opened it; a click in the terminal leaves it open. Inside the panel, plain keys scroll it (see `docs/changes-panel.md`) and never reach a PTY, and Escape closes it. A click on a card's diff stat opens it focused, with that card's terminal as the place Escape returns to. They skip project headers, wrap, and do not act while an overlay is open or the app is busy. Ctrl+Tab and Ctrl+Shift+Tab cycle the selected task's tabs. Cmd+1 through Cmd+9 jump to a tab, with the agent on Cmd+1. The native Agent menu lists the actions and keys. New's tooltip reads "New agent ⌘N" and terminal add/close controls show their shortcuts using the existing KeyTip component and theme tokens. Cmd+T adds a shell; Cmd+W closes the selected shell and does nothing on the pinned agent, so it never starts Close task. Each task keeps its selected tab. Picker cancellation, Settings dismissal, and Base branch completion/cancellation restore the previous focus. Close cancellation keeps its workflow-specific shell behavior. Selection changes scroll only enough to reveal the selected row; redraws leave manual scrolling alone. Shell startup focuses its view immediately and never reclaims focus on completion.

**Glass.** Frosted, and the look when background opacity is below 100%. At 100% the window is solid and blur does nothing. The saved default is opaque. Settings (`Cmd-,`) sets the theme mode and the light and dark themes, opacity from 0 to 100, blur radius from 0 to 255, whether frost covers the sidebar alone or the sidebar and the terminal, the terminal font size from 8 to 32 (default 14), and whether a notification plays a sound. Chrome type sizes stay fixed. The title bar uses the sidebar opacity, so the blur shows through it.

The app does this in `crates/shika/src/appearance.rs`. GPUI's window background is `Transparent`, not `Blurred`, because GPUI's blur has one fixed strength. The radius is the private `CGSSetWindowBackgroundBlurRadius`. A CSS `backdrop-filter` cannot see the desktop, so do not add one, and do not add `tokens/glass.css`. The browser mock's `blur(44px) saturate(1.9)` is only a stand-in for that native blur.

When glass is on, `chrome_for` in `crates/shika/src/appearance.rs` paints these tints. The column alpha is the Settings opacity. The values below are Shika Light and Shika Dark's; a derived theme keeps its own background for the column in glass, with the same alphas and the same solid popups.

- Light column: `#F6F8F2`. Dark column: `#181A17`. Solid mode stays `#F1F2EC` light and `#1A1C19` dark.
- Sidebar-only frost keeps the terminal at `1.0`. When frost covers the terminal, its alpha is the Settings opacity, down to a floor of `0.2` that only keeps it from vanishing; readability is the user's choice. CLI-colored cells stay opaque. The header is a step (`0.1`) more transparent than that surface, and never below half its alpha.
- Resting cards are 48% white in light glass and 4.5% white in dark glass, with a 1px top highlight. The selected card stays solid. Unseen ready cards use the ready tint at 78% in light glass and 62% in dark glass.
- Dialogs, the picker, the toast, and tooltips stay solid: light `#FAFAF7`, dark `#242722` for the overlay, and the toast's solid color. The window-server blur only reaches what is behind the window, and GPUI has no backdrop blur, so a translucent popup would show the cards and terminal text under it, sharp. No overlay dims the window: Settings previews opacity and blur on it, and the picker and dialogs match. The panel's shadow and ring separate it.
- The Changes panel follows the terminal: opaque with sidebar-only frost; when frost covers the terminal, its list takes the terminal's alpha and its title row the header's. Diff tints stay opaque, like CLI-colored cells.
- Hairlines and meta ink shift so they stay visible on the frost. Light glass meta ink `#5F6459`, hairline 10% black. Dark glass meta ink `#A6AB9E`, hairline 8% white.
- macOS Reduce transparency turns glass off: solid colors, no blur, terminal alpha `1.0`. The saved opacity is left as it is.

Hover washes and the notification stay translucent in both modes. Ink-5 separators shift too: `#ADB1A5` on light glass, `#5E6359` on dark glass.

GPUI's Metal blending adds alpha (source one, destination one), so a translucent fill painted over the translucent column comes out opaque: resting cards and washes in glass do not show the desktop through themselves. In light glass a resting card reads as a light grey rather than white frost. Fixing that needs a GPUI change.

**Status values in the app.** The oklch tokens converted to sRGB. Light: ready dot `#45B164`, text `#21763C`, tint `#EEFBF0`; asking `#ED8725` / `#AB5200` / `#FFF5E7`; working dot `#4493D0`, text `#266EA4`; waiting dot `#A3A79B`. Dark: ready `#68CA80` / `#89DA9B` / `#18241A`; asking `#F8A13F` / `#F6B669` / `#2B1F11`; working `#66ABE5` / `#8CC4F4`; waiting dot `#6B7065`. Asking values restore the existing archived/demo oklch tokens. Glass asking tint is `#FFF4DA` at 78% in light and `#3E290F` at 62% in dark. Asking cards retain their tint until resolved. Waiting text is ink-3. Failed PR checks: light dot `#DD4B3E`, text `#B42318`; dark `#F07A6B` / `#F59B8F`; derived themes use ANSI red with the same 4.5:1 text rule.

**Elevation in the app.** Selected card: 1.5px focus ring plus `0 2 6` at 7% ink (dark `0 2 8` at 30% black). Selected while the terminal has focus: a 1px `--line-selected-dim` ring. A resting card's 1px ring is a border, since a GPUI drop shadow would also paint under a translucent card. Dialogs and picker: `0 24 60` at 30% (dark 55%) plus a 0.5px ring. Toast: `0 6 20` at 35% black.

**Dark mode.** Settings' Theme row is System, Light, or Dark. System follows macOS, from `window.appearance()`, and paints the Dark theme pick in dark and the Light theme pick in light. Light and Dark force that side whatever macOS says: the app sets `NSApp.appearance` to Aqua or Dark Aqua, so the traffic lights, menus, and `window.appearance()` match, and System clears it. Same names, different values. Status colors get lighter and the tints become low-chroma charcoal. `Palette::shika_dark` is the dark terminal, on the column's charcoal. Dark chrome and dark glass are painted by `chrome_for`.

## Rules

Follow this file for color, type, spacing, layout, focus, motion, copy, and icons.

- Reuse the colors in `Chrome` (`crates/shika/src/appearance.rs`), the type sizes, radii, and shadows in `crates/shika/src/main.rs`, and the terminal palette in `crates/shika-terminal/src/theme.rs`. No color is written in `main.rs`. Never hard-code a new color, font size, radius, or shadow. If no value fits, stop and ask. Do not invent one.
- Build new UI from the views in `crates/shika/src/main.rs` and `crates/shika-terminal/src/view.rs` before writing new ones. New views use those same values and the states rest, hover, selected, selected-dimmed, and disabled.
- Status colors (asking, ready, working, waiting) are the only hues in the chrome. No brand accent. Selection and focus use ink. The diff green and red under Color are the one exception, and only inside the Changes panel's rows.
- Copy is sentence case. Status words stay fixed. Buttons are verbs that name the outcome. No emoji. No exclamation marks. The longer copy rules are under Content fundamentals.
- Every action with a shortcut shows its key. Typing in the terminal or a text field never triggers app shortcuts.
- Every UI change must work in both light and dark mode, and with a derived theme. Check them before finishing.
- Theme the terminal with `Palette` in `crates/shika-terminal/src/theme.rs`. `shika_light` and `shika_dark` are the Shika palettes; other themes are entries in `crates/shika-terminal/src/catalog.rs`, whose chrome is derived, never hand-written in `main.rs`. A new chrome field needs a Shika value and a derivation rule. JetBrains Mono is already bundled under `assets/fonts/` (OFL).
- Glass is the Glass section of this file, applied by `crates/shika/src/appearance.rs`. At 100% opacity the window is solid. Below that, use the glass tints. When frost covers the terminal, its alpha follows the opacity down to 0.2. Do not add a CSS glass file.
- If you add a color, size, radius, or a new view, update this file in the same change.
